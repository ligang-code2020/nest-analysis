## Middleware 模块
中间件是在路由处理程序之前调用的函数。中间件函数可以访问请求和响应对象，以及应用程序请求-响应周期中的 next() 中间件函数。 下一个中间件函数通常由名为 next 的变量表示。
> 中间件函数可以执行以下任务：
> * 执行任意代码。
> * 修改请求和响应对象。
> * 结束请求-响应周期。
> * 调用堆栈中的下一个中间件函数。
> * 如果当前中间件函数没有结束请求-响应循环，它必须调用 next() 将控制权交给下一个中间件函数。否则，请求将被挂起

### Middleware 和 Interceptor 的区别
Middleware 工作在较低级别的 HTTP 层面，其主要职责是处理请求前后的操作，比如身份验证、日志记录、CORS 设置等。
由于响应体通常是通过框架内部的管道（Pipes）、序列化器（Serializers）等组件生成的，并由底层的 HTTP 服务器（Express/Fastify）负责发送，因此 Middleware 并不直接参与响应体的生成过程

#### Middleware：

* 适用于简单的 HTTP 请求/响应处理任务。
* 可以访问 `res` 对象，但无法直接获取响应体内容。
* 更适合处理与 HTTP 协议相关的逻辑，如日志记录、身份验证、CORS 等。

#### Interceptor：
* 提供了更高的灵活性和功能，支持依赖注入。
* 可以直接访问并修改控制器返回的数据（即响应体）。
* 更适合处理跨切面的逻辑，如日志记录、性能监控、缓存控制等。


> Middleware 是 NestJS 请求生命周期中最先执行的一环，适合做请求预处理和响应后处理，
> 但无法直接访问控制器返回的数据（响应体）。

```ts
/* Middleware 生命周期图解 */

/*
┌────────────────────┐
│     HTTP 请求到达   │
└────────┬───────────┘
         ▼
┌────────────────────┐
│   Middleware 阶段   │←─── 可能有多个 Middleware 按顺序执行
│                    │
│  req → res → next() │
└────────┬───────────┘
         ▼
┌────────────────────┐
│    路由匹配阶段     │
└────────┬───────────┘
         ▼
┌────────────────────┐
│   控制器方法调用    │←─── 执行对应的 Controller 方法
└────────┬───────────┘
         ▼
┌────────────────────┐
│   Interceptor 阶段   │←─── 如果配置了拦截器，在控制器前后执行
└────────┬───────────┘
         ▼
┌────────────────────┐
│     Pipe 验证       │←─── 参数转换与验证（如 ValidationPipe）
└────────┬───────────┘
         ▼
┌────────────────────┐
│   Exception Filter  │←─── 异常捕获与处理
└────────┬───────────┘
         ▼
┌────────────────────┐
│   返回响应给客户端  │
└────────────────────┘

 */
```
